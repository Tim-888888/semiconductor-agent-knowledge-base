# T9-4.4.6c-2 通用语料标准化验收

## 1. 结论

`T9-4.4.6c-2` 已建立面向未知未来上传内容的通用语料标准化服务。文档、表格、图片、多文件和 ZIP
快照使用同一套契约、API、Worker、Parser Dispatcher、Sidecar/Profile 和暂存复核流程；候选公开资料
没有来源专用分支、专用 Chunk、预置答案或检索结果。

本阶段只生成不可变原始快照、可审核派生物和标准化报告。所有任务最终为 `review_required`，不会创建
知识 Document/Chunk，也不会写入活动 Milvus。批量发布、密封盲测和 `demo-public-v1` 仍属于
`T9-4.4.6d`，尚未开始。

## 2. 通用处理链路

1. API 接收多个文件或一个 ZIP、Corpus 元数据及声明式 Sidecar/Profile，先写私有 MinIO 原始快照。
2. Worker 校验幂等键、快照 Hash、总大小、文件名和声明式规则，再安全展开 ZIP。
3. 统一 Parser Dispatcher 判定文档、表格、标签、图片、归档或未支持文件，不读取来源名称决定路由。
4. 文档生成规范 Markdown；表格和标签只生成有界数据画像，禁止原始行逐条向量化；图片复用现有 VLM
   生成客观 `image_text`；未支持安全文件保留原件并产生稳定警告。
5. 跨文件关系只接受 Sidecar 明确声明，不根据文件名猜测标签、图片或答案关系。
6. MongoDB 保存任务、事件、文件清单和审核报告，MinIO 保存原件与派生物；审核通过前不进入知识发布链路。

公共 API 为管理员路由：

- `POST /api/v1/corpus-standardization-jobs/upload`
- `GET /api/v1/corpus-standardization-jobs`
- `GET /api/v1/corpus-standardization-jobs/{job_id}`
- `POST /api/v1/corpus-standardization-jobs/{job_id}/retry`

生产模式由 Celery 任务 `semikb.corpus.standardize` 执行；MongoDB 仍是业务状态真相，Redis 只负责投递。

## 3. 安全与通用性门禁

- ZIP 拒绝路径穿越、大小写重复、符号链接、加密成员、嵌套压缩包和危险脚本，并限制成员数、单文件/
  总解压大小及压缩比。
- MIME 映射由项目固定，避免操作系统差异改变 CSV 等格式识别。
- `.data` 等无标准扩展名文件只能通过对所有用户开放的声明式分隔符、表头和角色规则进入通用表格路径。
- 表格画像限制采样行数和列数；标准化报告不保存原始数据行、Prompt、密钥或第三方原始异常。
- 同一 Corpus/Snapshot/幂等键重复提交可复用；同一键内容变化返回冲突，不覆盖已有快照。
- Job 创建者必须来自已鉴权 Actor，公共契约没有 Demo 用户默认值；临时存储/Provider 错误使用安全稳定
  错误码进入 Celery 有界重试，不向客户端泄漏第三方异常。
- 来源、文件或 Corpus 更名不会改变处理结果；没有任何 `if source == ...` 或候选来源名称判断。

## 4. 真实公开资料验收

两类差异明显的真实公开资料通过与浏览器临时文件完全相同的 API/Worker：

| 语料 | 结果 | 审核边界 |
| --- | --- | --- |
| UCI SECOM ZIP | 4 个文件；`.data` 为 table、labels 为 label、`.names` 安全保留；1 条显式关系 | 数据画像只观察 200 行，590 列按上限截断；原始行不向量化 |
| arXiv 2411.11029 PDF | 1 个 document，经 PDF Parser 生成规范 Markdown | 只进入暂存审核，不发布到知识索引 |
| 浏览器 Markdown + CSV | 2 个文件，自动识别为 mixed；1 文档/1 表格，0 警告 | 使用普通上传表单，无来源专用参数 |

公开资料原件没有提交 Git，只保存在 ECS 私有 MinIO。来源、许可、URL、版本和限制保存在任务元数据中。

## 5. 存储与迁移验收

新增 `corpus_standardization_jobs`，唯一约束覆盖 `job_id`、`idempotency_key` 和
`metadata.corpus_id + metadata.snapshot_version`，另有状态时间索引。版本化迁移
`t9-4.4.6c2-corpus-standardization-v1` 只创建四个批准索引：首次 dry-run 为四个 `create`，应用成功后
再次 dry-run 为 `actions=[]`；快照保存在 ECS 私有迁移目录。

真实两条公开资料任务前后计数：

| 对象 | 前 | 后 | 解释 |
| --- | ---: | ---: | --- |
| MongoDB `document_catalog` | 36 | 36 | 未创建知识文档 |
| MongoDB `chunk_catalog` | 87 | 87 | 未创建知识 Chunk |
| MongoDB `corpus_standardization_jobs` | 0 | 2 | 只增加标准化业务记录 |
| MinIO `corpora/` raw | 0 | 5 | 不可变原始对象 |
| MinIO `corpora/` derived | 0 | 5 | 审核用派生对象 |
| Milvus 活动行 | 123 | 123 | 未污染活动检索索引 |

两个私有 Bucket 共用稳定键前缀 `corpora/{corpus_id}/{snapshot_hash}/{category}/{relative_path}`：
`semikb-raw` 使用 `sources/expanded` 类别，`semikb-derived` 使用 `reports/standardized` 类别，路径片段
经过稳定编码。只重建 API、Worker、Web，MongoDB、Milvus、两个 MinIO、etcd 和 Redis 六个受保护
容器 ID 前后不变。
