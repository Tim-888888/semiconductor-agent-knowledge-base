# 样例数据与黄金集

`data/fixtures/demo_corpus.json` 和 `data/assets/` 完全由项目构造，不包含真实 Fab、客户、
Recipe 参数或生产数据。所有文档逐条显式记录 synthetic source URI、CC0-1.0、版本、审批、
有效期、`access_scope_key`、Fab/Product/Tool/Chamber 范围。

## 当前数据

| 类型 | 内容与用途 |
| --- | --- |
| SOP R1/R2 | 历史/现行版本过滤和 supersedes 版本链 |
| Recipe V2.2/V2.3 | 独立 Recipe 历史/现行版本、虚构参数窗口和审批约束 |

| 晶圆图 | Edge-ring 与正常对照两张 320×320 PNG，文本可召回并经鉴权接口返回真实文件 |
| SPC | 120 行 15 分钟时序 CSV，包含 Lot/Wafer/Tool/Chamber、CL/UCL/LCL 和 5 个 OOC 标签 |

资产可以通过以下命令确定性重建，重建结果必须与语料中保存的 SHA-256 一致：

```powershell
conda run -n dl python scripts/generate_demo_assets.py
```

## 通用标准化与数据泄漏边界

- 上表候选来源是通用流水线的开发样本，不是允许写来源专用代码的白名单。项目语料与未来用户上传必须
  使用同一套 Manifest、批次/Sidecar、Parser Dispatcher、质量门禁、API/Worker 和发布流程。
- 禁止根据来源名、文件名、Document ID、演示问题、预期答案、预期 Chunk 或评测标签硬编码解析、切分、
  路由、分数、召回结果或回答。来源差异只能通过对所有用户开放的声明式 Profile/Sidecar 表达。
- 用户没有提供且无法从可信来源验证的 Fab、Product、Tool、Recipe、许可、批准状态或根因必须保持未知，
  进入澄清、隔离或人工复核，不能套用 Demo 默认值，也不能由模型推断成事实。
- 当前九格式黄金文件验证格式与系统链路；它们与 `demo-v1/v2`、意图 v1/v2/v3 都属于演示或回归证据，
  不能单独证明系统对未知文件和未知问题的泛化能力。

## 评测数据分层

| 类型 | 可否用于调参 | 用途 |
| --- | --- | --- |
| development | 可以 | 调试解析、标准化、治理和失败诊断 |
| calibration | 可以 | 选择阈值、Top-K、Chunk、Prompt 和检索配置 |
| regression | 不用于宣称无偏泛化 | 固定旧行为、防止功能回退、演示彩排 |
| holdout | 不可以 | 参数冻结后验证未见文件、未见结构和未见问题；打开后若修改实现，必须换新版本 |

评测数据必须记录用途、Hash、来源快照、`sealed_at`、`opened_at` 和泄漏审计状态。开发/校准样本不得进入
同版本 holdout；演示问题不得计入盲测指标。
