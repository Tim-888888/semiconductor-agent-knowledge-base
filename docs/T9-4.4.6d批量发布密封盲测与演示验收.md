## 2. 实现范围

- 新增版本化 Corpus Publication Batch 契约、MongoDB 业务真相、Celery 任务和管理员 REST API。
- 发布只接受已完成标准化、已人工批准且明确确认质量警告的不可变 Corpus 快照。
- 每个发布项复用既有受治理入库服务，生成标准 Document、Chunk、Image/Table、MinIO 派生物和
  Milvus 活动投影；正文和资产仍分别由 MongoDB/MinIO 管理，Milvus 不保存正文。
- 发布结束后逐文档核对 MongoDB Catalog、MinIO 对象和 Milvus 行；对账失败时批次不标记完成，
  可通过不可变 revision 重试和补偿，不覆盖历史执行证据。
- 新增 development、calibration、regression、holdout 四类评测数据及发布冻结契约。未打开的
  holdout 通过 API 只返回治理元数据，不返回 Case 正文。

## 5. 意图与检索验收修正

公网浏览器首次查询已批准公开语料时，发现旧意图卡把“外部资料”过度绑定 Web，且“不要使用 Web”
没有被确定性策略识别。修复采用通用能力边界，没有加入 SECOM、论文标题或演示问题特例：

- 默认目录升级为 `semikb-intent-catalog-v4`，活动卡 15 张。
- `knowledge.governed_corpus_lookup` 统一描述已批准进入内部知识库的数据集、论文、数据卡和公开资料。
- 明确否定 Web 时强制 `internal_rag`；允许 Web 时仍可按受控组合进入 `rag_and_web`。
- 仅出现“知识库”三个字不能绕过域外拒绝，必须同时具有受治理语料对象和查询语义。
- v1/v2/v3 冻结集通过迁移覆盖层兼容，不修改其原文件或 Hash；旧 `history_direct` 产生率仍为 0。

在线探针验证普通受治理语料问题均走 `internal_rag`，域外诗歌请求走 `refuse`。明确“不要使用 Web”的
真实工作台请求只产生 Dense、Sparse、RRF 和 Reranker Trace，没有 HyDE/Web 阶段，并返回 UCI 数据卡
证据。
