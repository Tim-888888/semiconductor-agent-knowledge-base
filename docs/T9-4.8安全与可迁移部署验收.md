# T9-4.8 安全与可迁移部署验收

## 1. 验收结论

2026-08-23，T9-4.8 已在测试 ECS 完成。公网仅监听 `22/80`，MongoDB、Milvus、MinIO、etcd 和
Redis 均未发布宿主机端口；JWT、RBAC、线程隔离、访问码限流、短时图片链接、日志脱敏、应用容器
最小权限和离线镜像迁移全部通过。T9-4/T9 尚未完成，下一步只有 T9-4.9 最终演示验收。

## 2. 安全加固

1. 生产环境的 Demo Token 不再接受客户端自报的用户、角色或数据范围。服务端固定签发
   `demo_engineer`，角色固定为 `engineer + knowledge_admin`，Scope 固定为 `demo_engineering`。
2. `/api/v1/demo/seed` 在生产环境对匿名请求返回 401，对已授权请求返回 404，不允许修改生产数据。
3. 无效和过期 JWT 均返回 401；工程师角色访问知识管理员接口返回 403；跨用户线程读取返回 404。
4. 访问码缺失或错误返回 401；Nginx 按来源地址限流，连续错误请求出现 429。
5. 图片必须先通过业务 API 鉴权，签发约 300 秒的短时地址；未授权访问和自然过期后访问均返回 403。
6. Nginx 访问日志只记录 `$uri`，不记录 query string 或 Referer，避免对象签名参数进入日志。
7. API/Worker 使用 UID/GID `10001:10001`，Web 使用 `101:101`；三者均为只读根文件系统、
   `cap_drop=ALL`、`no-new-privileges=true`、非 privileged。Web 在容器内监听 8080，由宿主机 80 转发。
8. 根目录 `.env` 权限为 `0600`。Git 跟踪文件、当前应用日志、镜像配置和前端静态文件的真实密钥
   精确扫描均为 0 命中。

完整黑盒结果见 `docs/evidence/t9-4-8/security-report.json`。

- 覆盖服务：etcd、Milvus MinIO、Milvus、MongoDB、业务 MinIO、Redis、Milvus Init、API、Worker、Web，
  共 10 个唯一镜像。
- `images.tar`：3,813,758,976 bytes，SHA-256 为
  `a63a3334417737ccd6c8549a038fc10ace18f1ac22c690c9ff253a439e6b645f`。
- `source.tar.gz` 由 `git archive` 直接从固定提交生成，不读取服务器脏工作区；归档不包含 `.env`、
  业务数据或凭据。

## 6. 测试环境例外

以下是用户已确认的测试环境例外，不视为正式生产标准已满足：

- 当前通过 HTTP 访问，尚未配置域名和 HTTPS。
- SSH 22 因多地点办公暂时对公网开放，并保留密码登录；正式发布前必须改为密钥登录并限制来源，
  或接入受控运维通道。
- MongoDB 当前为单节点；正式生产需升级副本集，重新验收事务、故障转移和恢复。

这些例外不阻塞面试 Demo 的 T9-4.8 验收，但必须在正式商用发布清单中保持为阻塞项。
