# 测试与验收计划

## 自动化验证

| 范围 | 测试 | 通过标准 |
| --- | --- | --- |
| 入库 | 哈希幂等、缺省可选字段、过期 Revision | 重试不重复写入，过期内容不可检索 |
| 检索 | SOP 版本、权限、图文召回 | 命中现行 SOP；无权图片返回 403 |
| 对话 | 最多两轮澄清、线程恢复 | 关键约束不足时不调用下游；同一线程保留上下文 |
| Trace | 用户隔离 | 非管理员不能读取其他用户 Trace |
| 评估 | 冻结黄金集 | 每个 Case 保存 Trace，输出 Recall@5/MRR |
| 前端 | 构建 | TypeScript/Vite 无构建错误 |

执行：`conda run -n dl python -m pytest -q`、`npm run build`、`docker compose config`。

## 人工验收顺序

1. 从空 Demo 启动 API 和 Web，提交现行 SOP 问题。
2. 提问缺少 Product/时间/设备的良率问题，确认最多两次追问且未检索。
3. 检索边缘环状缺陷，打开证据抽屉中的合成晶圆图。
4. 查看 Trace 的过滤、Dense/Sparse、RRF、Rerank 和截断结果。
5. 新建训练文档，检查入库任务阶段事件和幂等重试。
6. 运行 `demo-v1`，确认黄金集指标和失败项可以追溯。

填好 `.env` 后再运行 `python -m semikb.storage.preflight`。只有四个数据存储均显示
`connection verified`，才能开始真实资源的集成验收。
