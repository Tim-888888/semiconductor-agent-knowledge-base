## 4. ECS 真 Mongo 证据

迁移前只读统计：21 个线程缺新上下文字段，20 个线程包含未排序旧消息。两条陈旧 `running` 请求分别
超过 6 小时和 16 小时未更新，且没有线程租约；记录被保留，未删除或改写。

迁移 dry-run 扫描 21 个线程，计划为 53 条旧消息分配序号；apply 后再次 dry-run 为 0 个待变更线程。
回滚快照保存在服务器项目私有 `.tmp/t9431/migrations`，不含消息正文，最终权限为 `600`；临时上传源码
和服务器源码备份已清理。

`scripts/verify_t9431_context.py` 在真实 MongoDB 中全部返回 true：

- 精确最近消息；
- 旧历史摘要边界；
- 新仓库实例的重启恢复；
- 线程隔离；
- 同线程顺序控制；
- 同一 request 的陈旧租约恢复，不同 request 不可抢占；
- 单调消息序号；
- 临时旧线程迁移回滚；
- 临时数据清理。

常驻 API/Worker 只重建应用镜像，MongoDB、Milvus、MinIO、Redis 均未重启。公网入口健康检查返回
`status=ok`。真实 JWT HTTP 读取 `demo_engineer` 的 20 个旧线程返回 200，全部线程有
`context_version`，全部历史消息有 `turn_seq`；验收未输出会话正文。

替换 API/Worker 后发现 Nginx 仍缓存旧 API 容器 IP，旧 IP 被 Worker 复用时公网入口返回 502。只重建
Web 容器后重新解析 `api` 服务名，Web、API 均恢复 healthy，公网 HTTP 复验再次通过；数据容器未重启。
