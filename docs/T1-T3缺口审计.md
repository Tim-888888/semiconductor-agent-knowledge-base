### 审计发现的原始缺口

| ID | 缺口 | 完成标准 |
| --- | --- | --- |
| T2-G1 | 未配置服务返回 `configured=false`，但 `detail` 仍显示 `URI/API configured` | 返回明确的 `not configured` 与缺失变量名称，并有自动测试 |
| T2-G2 | Preflight/Provisioning 内部重复直接创建客户端，没有统一客户端工厂和超时/关闭约定 | 提供低耦合客户端工厂或上下文管理接口，并完成单元测试 |
| T2-G3 | 只有连通性检查，没有可重复的 Mongo 索引、MinIO 私有策略、Milvus schema/index/alias、Redis 配置核验命令 | 新增只读 verifier，输出结构化差异并在不一致时失败 |
| T2-G4 | Mongo 索引列表被一次性创建为复合索引；如 `ingestion_jobs(job_id,idempotency_key)` 不能保证 `idempotency_key` 单独唯一 | 先设计迁移方案，经用户审批后仅修改 `semikb` 项目索引并复验 |
| T2-G5 | `DocumentRevision/Chunk` 允许 `None` 的过滤字段，与 Milvus 默认非空 VARCHAR/INT64 字段不一致 | 明确 nullable/default 方案，并用最小实体插入/读取测试验证 |
| T2-G6 | 没有 T2 专项自动测试 | 覆盖缺失配置、异常脱敏、schema contract、索引定义和 verifier |
