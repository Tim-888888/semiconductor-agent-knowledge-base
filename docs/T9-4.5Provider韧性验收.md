## 2. 失败策略

| Provider | 重试与降级策略 | 最终失败语义 |
| --- | --- | --- |
| Embedding | 仅对 timeout、429、5xx 和传输失败做最多 2 次尝试 | 失败关闭，停止检索，不以伪向量继续 |
| Reranker | 同 Provider 有界重试 | 降级到已完成的 RRF，Trace 记录 `rrf_fallback` 和尝试明细 |
| LLM | 主 Provider 先有界重试，再按配置切备用 Provider | 只允许在输出首个可见 Delta 前切换；部分流后失败不得混接另一模型 |
| MinerU | 创建批次不重放；上传、轮询和下载等幂等步骤可重试 | 失败文档不发布，Job/Event 保存安全失败码和尝试明细 |
| OCR/VLM | timeout、429、5xx 和传输失败有界重试；非法结构不重试 | 失败图片所属入库任务不发布，不虚构图注/OCR/检测结果 |
| Web MCP | 有界异步重试和独立超时 | 只降级为内部证据回答，并写入 `internal_evidence_only` 警告 |

共享审计契约为 `semikb-provider-attempt-v1`，只保存 Provider、操作名、尝试序号、结果、稳定失败类型、
HTTP 状态、是否可重试、受限 `Retry-After` 和耗时。它不保存 Endpoint、API Key、Prompt、请求正文、
响应正文或内部异常堆栈。
