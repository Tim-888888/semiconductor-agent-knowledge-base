# T9-4.4.6c-1 通用化基线验收

## 1. 结论

`T9-4.4.6c-1` 已完成代码、兼容、真实 ECS 存储和浏览器流程验证。系统不再把 Demo 权限、制造上下文、
审批或发布状态当作公共默认值；未知文件默认暂存待复核，只有通过统一来源治理门禁后才允许进入活动
Milvus 索引。

本结论只说明通用化基线成立，不代表公开语料标准化、未知语料盲测或最终批量入库已经完成。

## 2. 公共契约与 Demo 隔离

- `ActorScope` 默认 `anonymous` 且不授予角色、Scope、Fab、Product、Tool 或 Chamber。
- 上传、Document、Chunk、Image/Table 的公共默认值为中性值；上传默认为 `draft + staged`，来源许可
  默认为 `unknown`，制造与权限字段允许为空。
- 直接请求 `approved + published` 时，Pydantic 契约要求提供已复核的治理字段，不能依赖服务端补值。
- Demo Actor、Scope、Source Manifest 和合成来源信息由独立 Demo Factory 显式装配。普通上传、解析、
  分块和检索不调用该工厂。
- 新增版本化契约证据：`docs/evidence/t9-4-4-6c-1/generalization-contract-v1.schema.json`。

## 3. 发布、恢复与跨存储边界

首次发布和下架恢复调用相同的 Source Manifest 校验器，统一检查：

1. revision 已批准且拥有明确 `access_scope_key`；
2. Manifest 存在、已批准，并与 document 的来源 ID、版本、Scope、数据集和许可字段一致；
3. 许可已声明或验证，再分发策略已经复核；
4. MinIO 原件 Hash 与 document 引用一致，可选来源快照 Hash 与 Manifest 一致；
5. 实际 Document Chunk、`image_text` 和表格边界包含在声明式 `ingestion_policy` 中；大型表格原始行不能
   直接向量化。

ECS 新建未知元数据上传 `T9446C1-NEUTRAL-UPLOAD R1`，结果如下：

| 存储/服务 | 验收结果 |
| --- | --- |
| API/Worker | Job 完成到 `staged` 100%，没有错误发布 |
| MongoDB | Document 为 `draft + staged`、Scope 为空，任务和阶段历史完整，生成 1 个暂存 Chunk |
| MinIO | 原件和解析 Markdown 均存在 |
| Milvus | 最终该 `document_id` 为 0 行，活动检索无法召回验收哨兵文本 |

旧 MongoDB 文档不做破坏性迁移，仍可读取和检索。旧 revision 如果缺少合格 Manifest，再次发布或恢复时
会关闭失败，必须由管理员先补齐并复核治理信息。

## 4. 检索与评测治理

- 受保护证据由 `retrieval_policy=protected` 决定，不再从 `SOP-` 或其他 Document ID 前缀推断。
- 上游结构化理解写入 `retrieval_mode=standard/diagnostic/image`；条件 HyDE 和图片证据加权只读取该模式，
  不读取来源名、文件名或演示问题关键词。
- Retrieval Trace 记录检索策略版本，便于定位规则和结果变化。
- `EvaluationDataset` 区分 `development/calibration/regression/holdout`，保存密封时间、首次打开时间、来源
  快照 Hash 和泄漏状态；holdout 未密封或未通过泄漏复核时拒绝运行。
- `EvaluationRun` 冻结数据用途和治理快照。首次运行 holdout 只写一次 `opened_at`；非法检索 Profile 不会
  提前打开密封数据。
- 旧 `demo-v1` 与意图 v1/v2/v3 继续作为回归证据读取，冻结 Hash 不变。
