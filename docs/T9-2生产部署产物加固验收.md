# T9-2 生产部署产物加固验收

## 1. 范围与结论

T9-2 已按用户确认的 **4 vCPU / 8 GiB / 80 GiB、Alibaba Cloud Linux 4、全栈单机、HTTP 测试入口**
完成本地部署产物加固。该阶段只修改仓库代码和文档，没有连接、安装或修改新 ECS，也没有改动旧
CentOS 上的 MongoDB、Milvus、MinIO、Attu 和 Redis。

本阶段完成不等于 T9 完成。镜像拉取与构建、Moby 安装、真实容器启动、空存储初始化、合成语料入库、
浏览器工作流、容量监控和备份恢复演练仍属于 T9-3/T9-4。

已确认的测试机基线为华东 1（杭州）、`ecs.u1-c1m2.xlarge`、4 vCPU/8 GiB、80 GiB ESSD Entry、
Alibaba Cloud Linux 4 LTS 64 位容器优化版和 100 Mbps 峰值公网带宽。公网/私网 IP、登录凭据和
服务器真实 `.env` 只保存在 Git 忽略的本地配置中，不写入公开仓库；后续换机时重新生成配置。

## 2. 全栈单机拓扑

公网只发布 Nginx `80`。MongoDB、Milvus、etcd、双 MinIO 和 Redis 均不映射宿主机端口。

| 网络 | 容器 | 作用 |
| --- | --- | --- |
| `edge` | Web、API、Worker | Web 到 API；API/Worker 访问在线模型服务 |
| `data`（internal） | API、Worker、MongoDB、Milvus、etcd、双 MinIO、Redis | 业务数据与任务通信 |
| `assets`（internal） | Web、业务 MinIO | Nginx 代理短时预签名图片，不让 Web 进入完整数据网络 |

应用容器使用非 root 用户、只读根文件系统、`no-new-privileges`、`cap_drop=ALL` 和临时目录。
全部容器配置日志轮转、健康检查、PID、CPU 和内存上限。Worker 固定 `concurrency=1`；Nginx、API
与临时目录按 100 MiB 单文件上限对齐，避免 8 GiB 单机在 200 MiB 上传路径发生不可控峰值。

## 3. 冻结镜像与资源预算

| 服务 | 冻结镜像 | 内存上限 |
| --- | --- | ---: |
| Milvus | `milvusdb/milvus:v2.5.5` | 2560 MiB |
| etcd | `quay.io/coreos/etcd:v3.5.18` | 256 MiB |
| Milvus MinIO | `minio/minio:RELEASE.2023-03-20T20-16-18Z` | 384 MiB |
| MongoDB | `mongo:8.2.6` | 768 MiB |
| 业务 MinIO | `quay.io/minio/minio:RELEASE.2024-12-18T13-15-44Z` | 384 MiB |
| Redis | `redis:7.4.10-alpine` | 128 MiB |
| API | `python:3.12.11-slim-bookworm` 自建 | 640 MiB |
| Worker | 同 API 镜像 | 896 MiB |
| Web | `nginx:1.27.5-alpine3.21` 自建 | 64 MiB |

常驻上限约 5.94 GiB，另有 128 MiB 的一次性 Milvus 初始化容器；剩余内存供 OS、Docker、页缓存和
短时峰值使用。CPU 上限是可竞争配额，不是预留；T9-4 必须观察 OOM、Swap、Milvus 加载和 P95 延迟，
若 8 GiB 不稳定则升级 16 GiB，不继续压缩。

## 4. 配置与鉴权

服务器真实配置固定为 `/opt/semiconductor-agent-knowledge-base/.env`，权限 `600`。以下命令从本地
已填写 `.env` 复制在线 Provider 配置，同时生成全新的 JWT、测试访问码和全部存储密码；不会复制
`DEPLOY_*`、SSH 密码、旧内网地址或工作站存储连接。

```powershell
conda run -n dl python scripts/deployment/generate_server_env.py `
  --source .env `
  --output data/runtime/deployment/.env.server
```

生成文件位于 Git 忽略的 `data/runtime/`。新服务器应使用新生成的基础设施密码，不能跨服务器复用。
公网测试工作台先要求 `DEMO_ACCESS_KEY`，随后才允许签发一期 scoped Demo JWT；生产模式缺少访问码时
接口关闭。Nginx 对该入口限速，并增加 CSP、禁止 iframe、安全内容类型和权限策略响应头。

Milvus 开启鉴权，一次性 `milvus-init` 只在首次部署时把默认 root 密码改为生成值，重跑时验证当前密码
后幂等退出。MongoDB 首次初始化创建项目专属 `semikb_app` 用户；业务应用不使用 MongoDB root。
一期业务 MinIO 与 Milvus 仍使用各自内部 root 凭据，这是测试单机的已知限制，正式生产应再细分策略。

## 5. T9-3 执行顺序

1. 安全组整改并复核：新增 `80/tcp`；`22/tcp` 仅允许用户公网 IP；删除公网 `3389`；数据库和存储端口不开放。
2. 在 Alibaba Cloud Linux 4 上人工执行 `scripts/deployment/install_moby_alinux4.sh`。脚本只支持该 OS，
   已有 Docker-compatible Engine 与 Compose 时不改包；安装方式依据[阿里云 ECS 官方 Docker 文档](https://help.aliyun.com/zh/ecs/user-guide/install-and-use-docker)。
3. 将仓库部署到 `/opt/semiconductor-agent-knowledge-base/`，把生成文件放为根目录 `.env` 并设 `600`。
4. 运行 `scripts/deployment/host_preflight.sh .env`；任何资源、密钥、端口或 Docker 检查失败都停止。
5. 首次测试部署执行：

```bash
cd /opt/semiconductor-agent-knowledge-base
./scripts/deployment/deploy.sh --seed-demo
```

`--seed-demo` 是显式写入开关，只写入仓库内 CC0 合成语料；不带该参数只创建空存储结构，不切换 Alias、
不写知识。种子流程沿用 T4 的哈希幂等、质量门禁、在线 Dense/Sparse、发布和 Alias 机制。

## 6. 数据目录、备份与恢复

- 数据：`/opt/semiconductor-agent-knowledge-base-data/`
- 备份：`/opt/semiconductor-agent-knowledge-base-backups/`
- 业务 Bucket：`semikb-raw`、`semikb-derived`

`backup_cold.sh` 会停应用和存储，归档全部绑定目录，并同时保存权限为 `600` 的匹配 `.env` 与 SHA-256。
恢复必须同时提供数据归档和同期 `.env`，且目标数据目录必须为空；否则脚本拒绝执行。恢复脚本只准备
独立数据副本和独立恢复环境，不停止 Compose、不覆盖线上数据根或项目 `.env`。这一设计保证 MongoDB、
MinIO、Milvus 和 Redis 的认证配置与数据快照一致，同时允许主栈与恢复栈并存验收。

```bash
T947_BACKUP_CONFIRM=cold-backup-t947 \
  ./scripts/deployment/backup_cold.sh --apply

T947_RESTORE_CONFIRM=restore-t947-independent \
./scripts/deployment/restore_cold.sh \
  --archive /opt/semiconductor-agent-knowledge-base-backups/semikb-<time>.tar.gz \
  --env /opt/semiconductor-agent-knowledge-base-backups/semikb-<time>.env \
  --target-data-root /opt/semiconductor-agent-knowledge-base-restore-t947-data \
  --restore-env /opt/semiconductor-agent-knowledge-base-backups/t947-restore.env \
  --project-name semikb-restore-t947 \
  --confirm-empty-target --apply
```

独立恢复验收后必须使用 `cleanup_t947_restore.sh` 的精确 Project/Marker 门禁清理副本，不能手工删除未知
路径。冷备会产生停机窗口，适合一期单机 Demo。T9-4.7 已在测试 ECS 完成真实独立恢复和内容级对账，
证据见 `docs/T9-4.7冷备恢复验收.md`。正式生产应升级 MongoDB 副本集、远端加密备份和独立对象存储策略。
