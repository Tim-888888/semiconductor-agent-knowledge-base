# T9-4.9 最终演示操作手册

## 1. 使用范围

本手册用于 SemiAtlas 面试 Demo 的启动前检查、8~10 分钟演示、自动验收、故障回退和迁移交接。
当前地址为 `http://112.74.99.143/`。访问码只保存在服务器根目录 `.env`，不得写入本文档、截图、
Git、命令历史或验收报告。

当前结论只适用于 4 vCPU、8 GiB 的测试 ECS。HTTP、公网 SSH 密码登录和 MongoDB 单节点仍是正式
生产阻塞项。

## 2. 演示前检查

在 ECS 执行：

```bash
cd /opt/semiconductor-agent-knowledge-base

docker compose --env-file .env -f docker-compose.prod.yml config --quiet
docker compose --env-file .env -f docker-compose.prod.yml ps
curl -fsS http://127.0.0.1/api/v1/health
docker exec semikb-worker-1 \
  celery -A semikb.workers.celery_app inspect ping --timeout 10
```

通过标准：API/Web 和六个数据服务健康，Worker 返回 `pong`；宿主机只监听 22/80，不公开 MongoDB、
Milvus、双 MinIO、etcd 或 Redis 端口；根目录 `.env` 权限为 `0600`。

## 3. 一键最终验收

完整验收必须使用空输出目录，脚本拒绝覆盖既有证据：

```bash
cd /opt/semiconductor-agent-knowledge-base

T949_ACCEPTANCE_CONFIRM=run-t949-final \
scripts/deployment/run_t949_final.sh --apply \
  --output-dir docs/evidence/t9-4-automated-1d1d1b6 \
  --bundle-dir /opt/semiconductor-agent-knowledge-base-offline/t949-1d1d1b6
```

脚本依次验证 9 个对话场景、SSE 时序、Trace、图片访问、三类运营页面数据、安全黑盒、短时链接过期、
离线镜像包、存储指纹、Worker 和健康检查。临时线程及其 Trace 会精确清理；运行后
`final-verdict.json` 必须为 `passed=true` 且存储差异为空。

## 4. 推荐演示顺序

1. 输入 `你好，你能做什么？`：展示自然气泡和能力边界，说明直接聊天不触发 RAG。
2. 输入 `ETCH-03 Chamber B 清腔后首片异常，当前 SOP 怎么要求？`：展示结构化调查卡、引用和任务终态。
3. 输入 `其中哪条证据提到了 RF match？`：展示复用证据账本，不重新发散检索。
4. 输入 `我刚才问了什么？`：展示同线程精确历史回顾和自然回答。
5. 新建线程后输入 `帮我查一下最近的良率异常。`，再补充
   `P-ALPHA，ETCH-03 Chamber B，最近24小时。`：展示通用澄清 Frame 和原任务恢复。
6. 输入 `找一张边缘环状缺陷的晶圆图，并说明应该先核对哪些证据。`：展示文本召回真实图片、首图
   自动预览、短时授权和来源回链。
7. 输入 `查 P-ALPHA ETCH-03 最近24小时 FDC 报警、修改 Recipe、生成报告`：展示查询完成、危险写入
   拒绝、报告延后三种独立终态。
8. 打开“可解释检索”：讲解 Dense/Sparse、RRF、Reranker、动态截断、Provider 尝试和阶段耗时。
9. 打开“入库任务中心”：展示九格式、阶段事件、Chunk/图片/表格产物及治理状态。
10. 打开“离线评估”：展示冻结数据、指标、失败 Case 和 Trace 下钻；失败 Case 是可观测缺口，不应
    包装成全部准确。

## 5. 页面判断标准

- `chat_direct/clarify/refuse` 使用自然气泡；RAG、证据复用和工具任务使用结构化调查卡。
- SSE 提交后先出现真实阶段状态，再出现一个或多个答案 Delta，最后才持久化完成消息。
- 最终授权证据有图片时，右侧自动打开第一张；无图片的新结果必须清除旧图。
- 桌面 `1440 x 900` 和移动 `390 x 844` 均不能产生横向溢出、文字遮挡或按钮移位。
- 浏览器 Console 必须为 0 error/warning；首次访问码页面产生的未授权探测不计入已登录工作台结果。

## 6. 故障处置

1. 公网 502：先检查 API/Web 健康；API 重建后必须强制重建 Web，使 Nginx 重新解析 API 容器地址。
2. Provider 超时：保留内部证据和已验证单元，按既有主备/降级策略结束；不得把失败重试做成无界循环。
3. Reranker 不可用：允许降级到 RRF，并在 Trace 中记录；Embedding 不可用则关闭检索，不能伪造结果。
4. Worker 失败：MongoDB 的 Job/Event 仍是业务真相；恢复 Worker 后按幂等键重试，失败任务不得发布。
5. 数据服务异常：停止演示，禁止删除容器、卷或数据目录；按 T9-4.7 冷备恢复手册在独立空目录演练。

## 7. 回退与迁移

当前固定源码提交为 `1d1d1b604b926709c865cea54465faa58e93cd3b`，完整离线包位于：

```text
/opt/semiconductor-agent-knowledge-base-offline/t949-1d1d1b6/
```

迁移到新服务器时：先校验 `SHA256SUMS`，加载 `images.tar`，解压 `source.tar.gz` 到
`/opt/semiconductor-agent-knowledge-base/`，再单独创建权限为 `0600` 的根目录 `.env`。镜像包不含
业务数据；MongoDB、Milvus、MinIO 和 Redis 必须使用 T9-4.7 的受控冷备迁移并在独立目录恢复对账。

如新版本应用回归，可重新加载前一个已验证离线包 `t949-7b4165f`，恢复其 `source.tar.gz` 后只替换
API/Worker/Web。任何回退前后都必须比较六个数据容器 ID 和跨存储指纹，不得回退数据卷来掩盖应用问题。

## 8. 演示表述边界

- 合成 SOP、Recipe、Case、制造工具数据必须明确称为模拟数据。
- UCI SECOM 和 arXiv 资料是受治理公开语料，不是 Fab 客户数据。
- `Observed rows` 且 `Sample truncated=true` 只代表有界预览，不能表述成完整数据集总样本数。
- 当前评估结果和容量测试只能证明当前数据/配置下的结果，不代表所有未知文件和问题都能正确处理。
- 当前系统已达到可重复的面试 Demo 标准，不应描述成已满足正式生产安全、容灾和容量要求。
