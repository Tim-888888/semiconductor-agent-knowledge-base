# 权限与版本治理

## 查询前强制过滤

检索和图片访问统一检查：`approval_status=approved`、`lifecycle=published`、生效时间、
过期时间、`access_scope_key`、Fab、Product 与 Tool/Chamber 范围。先过滤再向量检索；
Reranker 和 LLM 都不能看见被过滤的 Chunk。

图片不会把 MinIO 对象公开。客户端先调用资产访问 API，服务端按图片所属文档的当前版本和
Scope 重鉴权，才签发最多五分钟的预签名 URL。Demo 返回合成图预览，生产环境替换为 MinIO
预签名 URL。

## 发布与回滚

1. 原件、解析产物、Chunk Catalog 和 Milvus 暂存 Collection 先携带新 `index_version`。
2. 质量门禁验证审批、元数据、图片图注和向量数量。
3. 更新 `index_releases`，再将 `semikb_chunks_active` 指向新 Collection。
4. 将对应 Document Revision 标为 `published`；失败时只写补偿事件，不切 Alias。
5. 回滚只切换 Alias 和发布状态，不删除历史 Revision。

单机 MongoDB 阶段采用暂存、校验、发布、补偿。生产升级副本集后，应将发布标记与审计事件
包入事务，但 Milvus Alias 仍需要可重试的最终一致性补偿。

## 外部 Web 证据

阿里云 Web Search MCP 只能由项目网关调用，模型不直连 MCP。网关需要 API Key、超时、域名
白名单和净化策略；外部结果标记 `external`，只作补充，不能覆盖内部 SOP、Recipe 或已批准 Case，
更不会写入受控知识库。
