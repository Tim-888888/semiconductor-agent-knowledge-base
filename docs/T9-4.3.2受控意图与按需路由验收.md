# T9-4.3.2 受控意图与按需路由验收

## 1. 结论与边界

2026-08-13，T9-4.3.2 已完成本地开发、全量回归和目标 ECS 真实服务验收。系统现已能在每轮消息中
识别任务、会话、反馈、控制、澄清回答和混合输入，并由确定性 `RoutePolicy` 决定是否使用历史、
知识检索、制造数据、Web、澄清或拒绝。

本结论只覆盖理解、路由、槽位操作和逐任务策略决策。T9-4.3.3 的预定义组合执行、路由专用生成/校验、
逐任务最终结果及前端路由标识尚未开发；T9-4.3.4 的完整浏览器业务闭环也未开始。T9-4 和 T9 仍未完成。

## 2. 实现内容

- L0 使用模块级预编译规则处理精确历史回顾、上一轮回答变换、反馈、取消、纠正、固定问候和明确 OOD；
  命中后不调用意图 LLM。
- 复杂输入只调用一次结构化 LLM；输出经过严格 JSON Schema、Pydantic 校验，最多一次修复，失败后进入
  确定性降级。LLM 只返回语义建议，不拥有最终路由权。
- `ConversationUnderstanding` 固定交互模式、一级意图、最多 3 个 `task_items`、独立情绪信号、槽位操作、
  上下文消息引用、独立查询、取消范围和建议路由。
- `RoutePolicy` 只允许 9 种固定路由，并按路由风险使用不同置信度阈值；缺少关键字段时先澄清，越权和
  Recipe 写操作在下游调用前拒绝。
- 诊断/排查优先于普通 SOP 查询；总体调查固定联合知识与制造数据。模型补充的实体必须同时满足原文
  落地和槽位类型格式，不能把 Tool ID 当成 Chamber。
- 明确的 Recipe 修改由服务端固定为 `refuse`；报告生成在 T9-4.3.3 完成组合执行前固定为 `defer`，
  不允许模型把高风险或未实现任务降级为可执行项。
- `history_direct`、`chat_direct`、`tool_only` 和 `reuse_evidence` 都记录跳过检索原因；证据复用前重新
  校验当前 ACL、文档状态、版本、有效期和检索约束。
- Tool 纠正会使依赖旧 Tool 的 Chamber、Recipe 与证据引用失效，同时保留无关 Product。
- `agent_message_requests` 持久化路由、任务决策、上下文引用、槽位操作、失效引用、取消范围和有限情绪
  枚举，不保存隐藏推理、系统 Prompt 或密钥。新增字段均为可选字段，不需要破坏性 MongoDB 迁移。

## 4. 真实链路证据

`scripts/verify_t9432_agent_routes.py` 在 ECS 的真实 MongoDB、Milvus、在线模型和生产配置中创建临时线程，
完成后自动清理。14 项断言全部为 true：

- 精确历史直答和反馈均跳过 Retrieval、Tool 与 Web；
- `tool_only` 只调用制造数据，不调用向量检索；

- Tool 纠正不调用下游，并使 Chamber 等依赖失效；
- 越权 Tool 在下游前拒绝；
- 8 条请求均在 MongoDB 请求台账保存路由审计字段。

该场景实际累计调用 `retrieval_search=1`、`tool=3`、`web=0`；其余应跳过的场景调用计数没有增加。
