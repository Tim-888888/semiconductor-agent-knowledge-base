# T9-4.4.4 受控入库集成验收

## 1. 结论

T9-4.4.4 已把独立 `semikb_ingest` 包接入原有受控入库链路。`rag_ingestion` 不依赖具体 DOCX、XLSX、
PPTX、MinerU 或 Qwen 实现，只消费冻结的 `semikb-ingest-v1` 契约，并将统一 Draft 映射为
`DocumentRevision`、`Chunk`、`ImageAsset` 和 `TableAsset`。

本阶段完成的是本地代码集成、兼容性、自动测试和迁移方案，不包含逐格式真实黄金文件、ECS 部署、
三类真实存储对账、检索问答或浏览器点击。这些仍属于 T9-4.4.5，T9-4 和 T9 均未完成。

## 2. 运行链路

```text
上传原件
  -> 扩展名/MIME/Magic Bytes/OOXML 联合路由
  -> 精确格式 Parser + 显式 Provider
  -> semikb-ingest-v1 ParsedDocument
  -> Parser/Provider/上游/警告/指标审计
  -> 图片字节与表格 JSON 持久化到 MinIO
  -> Draft 映射为受治理业务模型
  -> 权限、审批、引用完整性和图文质量门禁
  -> Chunk Dense/Sparse Embedding
  -> MongoDB Catalog + Milvus staged
  -> MongoDB/Milvus published + Alias/Release
  -> 任一步失败：Revision quarantined + 精确 Chunk 向量补偿
```

原件、幂等 Job、阶段 Event、Embedding、发布和补偿继续复用原实现。Parser 临时图片句柄只在单次
解析 Session 内存活；业务层成功写入 MinIO 后立即释放，解析包不知道 Bucket、权限或索引结构。

## 3. 数据映射

| 统一输出 | 业务记录 | 持久化位置 |
| --- | --- | --- |
| `ParsedDocument` | `DocumentRevision` + `IngestionJob` 解析审计 | MongoDB；规范化 Markdown 在 MinIO |
| `ChunkDraft` | `Chunk`，保留标题路径、页/Slide/Sheet 位置和稳定资产 ID | MongoDB 正文；Milvus 仅向量与过滤字段 |
| `ImageAssetDraft` | `ImageAsset`，保留原图、图注、OCR、检测摘要、来源位置 | MinIO 原图 + MongoDB 目录 |
| `TableAssetDraft` | `TableAsset`，保留 Markdown/HTML、表头、行列数、来源位置 | MinIO `table.json` + MongoDB 目录 |

`parser_name`、`parser_version`、`provider_name/version`、`upstream_commit`、`chunker_version`、解析警告和
指标同时进入 Job、Document 或 Release 审计。未参考上游或不使用 Provider 的 Parser 对应字段允许为
空；不得伪造来源。

## 4. 兼容与迁移

- 旧 Markdown/PDF 入口、幂等键、跨存储主键和 REST 路径不变。
- 新模型字段全部有 legacy 默认值，旧 MongoDB 文档可以继续反序列化，不强制破坏性回填。
- 无表格文档继续按旧四参数 Store 调用，兼容已有测试 Store 和窄实现。
- 新增 `table_assets` Collection，唯一索引为 `table_id`，普通索引为
  `(document_id, revision)`。
- `python -m semikb.storage.t9444_table_assets_migration` 默认 dry-run；`--apply` 只允许空集合和已批准
  索引；失败自动恢复。`--rollback <snapshot>` 发现业务记录时拒绝删除。
- 表格资产不进入 Milvus；Production Store 只把 Chunk 和 Embedding 交给向量仓库。

## 5. 错误与补偿

格式不支持、扩展名/MIME/签名冲突、Provider 未配置、超时、不可用、解析失败、空结果和质量门禁失败
均使用冻结稳定错误码。API 返回对应安全 HTTP 状态和 `{code, message}`，不泄露第三方异常、Endpoint
或密钥。Worker 只对 Provider 超时/不可用和既有临时错误执行有界重试。

测试注入 MinerU 超时后，Document、Chunk、Image 和 Table 均未发布；换为可用 Provider 后复用原件和
同一 Job 重试成功，`attempt` 增加且重复提交不增加资产或 Chunk 数量。

- Wheel：228,166 bytes，共 96 个包条目，其中 `semikb` 68 个、`semikb_ingest` 28 个。
- 凭据扫描：通过。

本机 Docker Desktop Linux daemon 未运行，因此没有伪造 API/Worker 镜像体积。本阶段也没有在 ECS
构建或替换容器；Linux 镜像实测必须在 T9-4.4.5 部署前完成并与当前基线比较。

机器可读结果见 `docs/evidence/t9-4-4-4/integration-results-v1.json`。
