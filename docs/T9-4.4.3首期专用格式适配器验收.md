# T9-4.4.3 首期专用格式适配器验收

## 1. 结论

T9-4.4.3 已在独立包 `semikb_ingest` 内完成九类首期格式适配器：Markdown、TXT、HTML、PDF、
DOCX、XLSX、CSV、PPTX 和 JPG/JPEG/PNG。所有适配器都返回冻结的
`ParsedDocument + ChunkDraft + ImageAssetDraft + TableAssetDraft`，并通过统一 `IngestDispatcher`
校验格式、Parser、Provider、源文件哈希和 Provenance。

本阶段没有修改现有 `rag_ingestion` 上传/Worker/发布链路，没有修改 MongoDB、Milvus、MinIO、API、
ECS 或浏览器工作台。因而“适配器已经实现”不等于“线上多格式入库已经可用”；接线属于 T9-4.4.4，
真实黄金文件和 ECS/检索/浏览器闭环属于 T9-4.4.5。

## 2. 统一实现

- `StructuredBlockChunker` 按标题路径组合相邻文本，表格和图片保持原子 Chunk，并把稳定资产引用映射到
  最终 Draft。
- `ProcessPayloadStore` 继续只保存进程内临时字节句柄，适配器不知道 MinIO 对象路径或业务权限。
- `build_parser_registry` 显式注册本地适配器；只有配置了相应 Provider 才注册 PDF 和图片适配器。
- Provider 缺失、超时、429/5xx、非法结构化输出和危险归档均使用 4.4.1 冻结错误码失败，不存在跨格式
  默认回退。
- Provenance 对参考 Knowhere 思路的格式记录固定 Commit，但本阶段仍未复制任何 Knowhere 源文件。

## 3. 格式能力

| 格式 | 实现能力 | 受控限制 |
| --- | --- | --- |
| Markdown | 标题、段落、列表、表格、代码块 | 不抓取远程/旁路图片 |
| TXT | UTF-8/GB18030 安全解码、段落 | 不猜测不存在的权威标题层级 |
| HTML | 清除 script/style/nav/header/footer/aside/form，恢复标题、正文、列表、代码和表格 | 不抓取 img/iframe/object/embed 外部资源 |
| PDF | MinerU 独立 Provider、`content_list.json` 页码、标题、正文、表格和图片资产 | Provider 失败不发布；本阶段未做真实 PDF ECS 闭环 |
| DOCX | OOXML 文档顺序、标题、段落、列表、表格、内嵌图片和精确哈希去重 | 不支持 DOC/DOCM |
| XLSX | 可见 Sheet、连续表格区域、表头、单位、合并单元格、公式缓存值 | 隐藏 Sheet 跳过；不执行公式；不支持 XLS/XLSM |
| CSV | 编码、分隔符、表头、单位和行列 | 有界行/列/单元格数量 |
| PPTX | Slide、标题、文本框、表格、图片、讲者备注和位置框 | 不调用 LibreOffice，不渲染为 PDF |
| 图片 | 原图字节、尺寸门禁、Qwen 图注/OCR/检测摘要和 `image_text` | 不生成视觉向量；VLM 不可用时不伪造描述 |

## 4. Qwen 图片理解

图片适配器使用独立 `QwenVisionClient`，复用现有 Qwen Endpoint/Key，并新增
`QWEN_VISION_MODEL=qwen3.7-plus` 与超时配置。请求采用 OpenAI 兼容多模态消息和 JSON 输出约束，模型只
负责描述可见证据；服务端校验 `caption`、`ocr_text`、`detection_summary`、置信度和语言字段。

已用项目合成晶圆图完成真实在线冒烟：模型 `qwen3.7-plus` 返回成功，生成 1 个 `image_text` Chunk 和
1 个真实图片资产，资产字节往返校验一致。脱敏证据见
`docs/evidence/t9-4-4-3/qwen-live-smoke-v1.json`，不保存 API Key、Prompt 或模型生成正文。

## 5. PDF 与 MinerU

`MinerUPdfClient` 隔离 MinerU 的上传、轮询和结果 ZIP 协议，`PdfMinerUParser` 只消费本项目类型化结果。
结果读取器优先解析 MinerU `content_list.json` 的 `page_idx`、标题、文本、`table_body`、`img_path` 和图注；
仅有 `full.md` 时允许保留 Markdown，但会给出“页码映射不可用”警告。

ZIP 读取设置成员数/解压总量限制，并拒绝路径穿越、绝对路径和重复路径。本阶段使用合成 MinerU 结果包
验证页码、表格和图片映射；没有把“协议测试”写成“真实 PDF 已在 ECS 入库”。

`beautifulsoup4 4.15.0`、`markdownify 1.2.3` 和 `lxml 6.1.1`。`requirements.lock` 已按 Linux / Python
3.12 / `--generate-hashes` 重新生成，`--require-hashes` dry-run 通过。

项目 Wheel 从 190,277 bytes 增至 219,489 bytes，增加 29,212 bytes；本地 Windows 下载的相关 Wheel
合计约 12.0 MiB，新安装发行包占用约 27.6 MiB。它们不引入新服务、本地模型、GPU、LibreOffice、Java
或 Knowhere 业务依赖。当前本机 Docker Linux daemon 未运行，且本阶段禁止改 ECS，因此没有伪造 Docker
镜像体积；Linux API/Worker 镜像实测放到 T9-4.4.4 接线后、部署前执行。机器证据见
`docs/evidence/t9-4-4-3/dependency-impact-v1.json`。

第三方许可已更新到 `THIRD_PARTY_NOTICES.md`。Knowhere 仍为“审计与参考”，Vendored source 数量为 0。
