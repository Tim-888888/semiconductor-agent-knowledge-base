## T9-3 新 ECS 实际组合

新 ECS 全栈 Compose 固定 MongoDB 8.2.6、Milvus 2.5.5、etcd 3.5.18、Redis 7.4.10、业务
MinIO 2024-12-18 和 Milvus 2.5.5 已验证组合对应的 MinIO 2023-03-20。服务端只发布 Nginx 80；
存储在 internal 网络中。Alibaba Cloud Linux 4.0.4 上实际使用 Moby 28.3.3、containerd 1.7.34
和 Compose 2.26.1；该组合已完成镜像构建、空存储初始化、7 份合成语料发布、存储结构验证、
公网 API/工作台和在线 Dense/Sparse/Reranker 检索烟雾验收。容量、长时间稳定性和备份恢复仍属于
T9-4，不能由本次启动结果替代。完整制品见 `docs/T9-2生产部署产物加固验收.md`，真机证据见
`docs/T9-3阿里云真机部署验收.md`。

当前真实服务已完成 `semikb_chunks_v4` 的 Dense HNSW、Sparse Inverted Index、`lifecycle`
字段读写及 `semikb_chunks_active` Alias 验收；`v3` 作为直接回滚投影保留，`v2` 继续保留历史投影。该结果证明当前连接目标
支持项目能力，但不替代 T9 对服务镜像标签和阿里云部署组合的最终冻结。

T6 已在当前 MongoDB 单机实例验证 14 个同线程 Checkpoint 的暂停/跨服务实例恢复。该结果只证明
一期功能持久化可运行；阿里云生产仍需升级副本集、备份恢复、最小权限和连接池/故障转移验收。

## T9-4.4.5 多格式镜像实测

2026-08-15 在 4 vCPU、8 GiB 的 Alibaba Cloud Linux 4 测试 ECS 使用生产 Compose 构建九格式运行时。
API/Worker 镜像均由 472,457,579 bytes 增至 517,384,487 bytes，增加 44,926,908 bytes，约 9.5%；
Web 镜像由 48,450,281 bytes 增至 48,450,306 bytes。增量包含 `python-docx`、`openpyxl`、
`python-pptx`、`Pillow`、`beautifulsoup4`、`markdownify` 和 `lxml`，不包含 Pandas 作为格式解析实现、
本地模型、Torch、CUDA 或 GPU 运行时。

当前 ECS 上 Markdown、TXT、HTML、PDF、DOCX、XLSX、CSV、PPTX 和 PNG 均已通过真实 API/Worker、
MongoDB/MinIO/Milvus 及在线 Provider 验证。该结果证明首期格式组合在当前 8 GiB 单机可运行，但不替代
T9-4.5 Provider 韧性、T9-4.6 容量和长时间资源稳定性门禁。

消息恢复继续使用现有 MongoDB 线程与请求台账，不新增服务或索引。结构化消息投影保存最多 64 条
已授权证据账本项，旧记录缺失该字段时使用空列表并可从请求结果补齐；气泡路由不保存证据账本。
该兼容变更已在当前 API/Worker/Web 镜像和公网刷新流程验证。
