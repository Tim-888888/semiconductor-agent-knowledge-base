# T9-4.2 SSE 全链路验收

## 1. 结论

2026-08-13，T9-4.2 在本地测试和目标 ECS `112.74.99.143` 上通过。当前线上版本为
`612d667`，已实现真实的 POST SSE 全链路，不使用前端伪打字机。T9-4.2 完成只解除
T9-4.3 门禁；T9-4 和 T9 仍未完成。

## 2. 已实现链路

```text
React 乐观显示用户消息
  -> fetch POST + ReadableStream
  -> Nginx SSE 专用无缓冲代理
  -> FastAPI StreamingResponse
  -> LangGraph custom/values 事件
  -> 检索、重排、证据事件
  -> gpt-5.6-luna 真实答案 Delta
  -> 回答校验
  -> MongoDB 原子追加助手消息并更新请求账本
  -> completed 返回规范线程、证据和 Trace
```

新增接口：

- `POST /api/v1/threads/{thread_id}/messages/stream`
- `GET /api/v1/threads/{thread_id}/message-requests/{request_id}`
- `POST /api/v1/threads/{thread_id}/message-requests/{request_id}/cancel`

事件覆盖 `accepted`、`stage`、`evidence`、`answer_delta`、`heartbeat`、`completed` 和
`error`。事件只包含可公开阶段、答案和已过滤证据，不输出隐藏推理、Prompt、密钥或异常堆栈。

## 3. 请求账本与持久化语义

MongoDB `agent_message_requests` 使用 `actor_user_id + thread_id + request_id` 唯一键：

- 相同请求完成后可重放，不重复追加消息。
- 相同 ID 配不同正文返回冲突；运行中重复提交返回冲突。
- 失败或取消可复用同一 ID 重试，`attempt` 递增，用户消息只保留一条。
- 只有回答校验和线程持久化均成功后才发送 `completed`。
- 注入最终持久化失败时只发送 `error`，请求记为 `failed`，不保存半截助手消息。
- 显式停止、页面刷新和卸载均调用取消路径；浏览器 `pagehide` 使用带鉴权的 `keepalive` 请求兜底。

真实停止重试用例最终账本为 `status=completed`、`attempt=2`，线程只有同一
`request_id` 对应的一条用户消息和一条助手消息。刷新断线用例最终为 `status=cancelled`、
`assistant_message_id=null`，刷新后页面只恢复一条用户消息。

## 4. 原始 SSE 时序

公网入口直接执行流式请求，完整 Agent 路径记录如下：

| 相对时间 | 事件 | 说明 |
| ---: | --- | --- |
| 94 ms | `accepted` | 请求已接收 |
| 97 ms | `stage: analyzing_request` | 开始约束分析 |
| 2347 ms | `stage: retrieving_evidence` | 开始检索 |
| 4044 ms | `stage: reranking_evidence` | 开始重排 |
| 4062 ms | `evidence` | 权限过滤后的证据就绪 |
| 4101 ms | `stage: generating_answer` | 开始模型生成 |
| 5811 ms | `answer_delta` | 130 字符 |
| 5999 ms | `answer_delta` | 72 字符 |
| 6343 ms | `answer_delta` | 71 字符 |
| 6435 ms | `answer_delta` | 9 字符 |
| 6443 ms | `stage: verifying_answer` | 校验回答 |
| 6448 ms | `stage: persisting_result` | 保存最终结果 |
| 6451 ms | `completed` | 数据库已保存后完成 |

事件在不同时间分批到达，证明 Nginx 没有把完整回答缓冲后一次性返回。该线程最终持久化角色为
`[user, assistant]`，消息数为 2。静默图任务测试还验证了超过配置窗口时会发送 `heartbeat`。

## 7. 验收中发现并修复的问题

1. 公网 HTTP 环境不提供 `crypto.randomUUID()`：改为 `crypto.getRandomValues()` 生成请求 ID。
2. 浏览器停止读取后服务端请求短时仍为运行中：新增显式取消 API、活动图任务中断和等待退出。
3. 旧流清理可能误删同 ID 新尝试的控制句柄：改为按控制对象身份清理。
4. 服务端先结束 SSE 时前端显示 `network error`：增加用户停止标志，统一进入可重试停止态。
5. 页面刷新期间 ASGI 清理可能被取消：增加受保护服务端清理任务和前端 `pagehide + keepalive` 取消。
