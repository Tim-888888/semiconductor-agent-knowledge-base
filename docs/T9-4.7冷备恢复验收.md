## 2. 安全实现

- `backup_cold.sh` 只有同时提供 `--apply` 和精确确认变量才执行；先停应用写入，再停六类数据服务，
  归档全部绑定数据，保存同期 `.env`、SHA-256 和不含凭据的 Manifest，失败时删除不完整产物并恢复主栈。
- `restore_cold.sh` 只准备独立副本，不执行 Compose；要求显式绝对路径、独立 Project、空目标和确认变量，
  拒绝线上数据根、嵌套路径、现有恢复环境、校验和不符和危险 Tar 成员。
- 恢复环境从同期备份生成，但只改写数据根、备份根、应用环境路径和 Compose Project；权限为 `0600`，
  不安装到项目根，不进入 Git 或验收证据。
- `cleanup_t947_restore.sh` 同时校验 Project、恢复环境和恢复标记，只对独立 Project 执行 `down`，确认
  容器清空后才删除恢复数据和环境。
- API/Worker 的 Compose `env_file` 支持 `SEMIKB_APP_ENV_FILE` 注入；未设置时仍使用原 `.env`，线上行为不变。

## 5. 失败门禁与清理

真实执行前验证了三类拒绝路径：

1. 环境副本校验和被篡改：返回 1，目标和恢复环境均未创建。
2. 恢复目标非空：返回 1，原 Sentinel 保留，恢复环境未创建。
3. 恢复目标等于线上数据根：返回 2，恢复环境未创建。

独立验收后，清理结果为恢复容器 0、恢复网络 0、恢复数据根不存在、恢复环境不存在；两张恢复专用构建
镜像也已删除。冷备归档、同期环境副本、校验文件和无凭据恢复计划继续保留在受限备份目录。
