## 1.1 已确认执行决策

| 决策项 | 已确认结论 |
| --- | --- |
| 香港 ECS 登录 | 用户已提供测试密码，并授权本项目后续访问香港 ECS 无需重复确认；秘密值不得写入文档、Git、日志或长期记忆 |
| 云盘与快照 | 为降低成本，云盘保持“随实例释放”，关闭自动快照；接受实例回收后本机数据丢失风险 |
| 旧站停写 | 迁移窗口允许暂停深圳旧站写入 |
| HTTPS | 使用现有 Nginx + Docker 化 Certbot HTTP-01 |
| 深圳 ECS | 本项目不执行释放；用户在香港环境稳定后自行决定和操作释放 |

由于目标云盘会随实例释放，本计划不再把云盘作为灾难恢复介质。香港实例外部必须至少保留一份经过
SHA-256 校验的冷备、同期环境副本和离线应用包；抢占回收后的恢复路径是重建 ECS、重新绑定原 EIP、
加载离线包并恢复冷备。

当前 DNS 已提前指向目标 EIP，但目标端尚未返回有效 HTTP 响应，也没有完成 HTTPS 握手。因此本次
真正的对外切换点不是修改 DNS，而是目标端通过全部预发布验收后启用 Nginx 入口。

## 2. 迁移边界与原则

1. 本次只做等版本迁移、HTTPS 和部署地址切换，不同时开发业务功能。
2. 本项目不删除、不清空或释放深圳源服务器；只在已批准迁移窗口内执行短时停写与冷备。
3. 不复制正在写入的 MongoDB、Milvus、MinIO、etcd 或 Redis 目录；业务数据只走 T9-4.7 冷备流程。
4. 应用只从固定 Git Commit 和固定镜像恢复，不从脏工作区打包；当前未跟踪的面试文档不进入迁移包。
5. 备份归档、同期环境副本、离线镜像和源码包必须分别完成 SHA-256 校验。
6. `.env` 不进入 Git、镜像、命令输出或验收证据，服务器权限固定为 `0600`。
7. 新旧环境不能同时接受业务写入，避免产生两个无法自动合并的数据分支。
8. 任何跨存储内容不一致、权限泄露、TLS 失败或核心场景失败都判定为 No-Go。

## 4. 执行计划

### M0：冻结迁移窗口和变更边界

输入：用户确认的迁移时间、当前代码和源服务器状态。

执行：

1. 明确迁移开始与结束时间，暂停同期业务开发和线上数据治理操作。
2. 记录源端 Commit、Compose Hash、容器镜像 ID、六类数据容器 ID 和跨存储业务指纹。
3. 确认源端没有运行中的会话请求、入库、标准化、补偿或评估任务。
4. 目标域名已经指向香港 EIP，迁移期间目标端保持维护状态，不提前开放未验收应用。

输出：迁移批次 ID、源端基线、任务清空报告。

验收：不存在进行中的写任务，源端基线可重复读取。

### M1：目标 ECS 只读预检

输入：已授权的香港 ECS 登录凭据、EIP 和安全组配置。

执行：

1. 检查 Alibaba Cloud Linux 4、x86_64、4 vCPU、8 GiB、磁盘、时间同步和外网连通。
2. 确认 EIP `47.76.218.205` 已绑定目标实例；记录“云盘随实例释放、自动快照关闭”的已接受风险。
3. 检查 22/80/443 和宿主机防火墙；数据库与存储端口不得开放。
4. 确认 `/opt` 空间、Docker 数据目录和目标部署路径没有名称冲突。

输出：目标主机预检报告。

验收：资源满足 4 vCPU/8 GiB Demo 基线，磁盘可持久恢复，无端口和路径冲突。

### M2：冻结当前应用迁移版本

输入：当前本地 Git 仓库。

执行：

1. 以迁移开始时确认的最新已验收 Commit 为唯一源码基线，当前候选为 `3ec44aa`。
2. 重新生成 T9-4.8 离线迁移包，覆盖 10 个生产镜像、源码归档、Manifest 和 SHA-256。
3. 从空 Docker Alias 状态重新加载并核对所有镜像 ID。
4. 不复用 `1d1d1b6` 旧包作为最终版本，避免丢失 T9-4.10/T9-4.10.1 前端修复。

输出：版本化离线迁移目录和验证报告。

验收：源码 Commit、源码包 Hash、镜像文件 Hash 和运行镜像 ID 全部一致。

### M3：准备目标运行时

输入：目标主机、经验证的离线包。

执行：

1. 使用既有 Alibaba Cloud Linux 4 安装脚本安装 Moby、containerd、Compose 和 Git。
2. 创建 `/opt/semiconductor-agent-knowledge-base/`、数据根、备份根和受限临时目录。
3. 加载固定镜像，解压固定源码，不从 Docker Hub 临时升级镜像。
4. 将源端同期 `.env` 作为迁移凭据基线，只修改经审计的主机相关配置；不得重新生成会破坏现有
   MongoDB、Milvus、MinIO 或 Redis 数据访问的密码。
5. `.env` 权限设为 `0600`，运行 Compose `config --quiet` 和 `host_preflight.sh`。

输出：尚未承载业务数据的目标运行时。

验收：离线镜像完整、Compose 可解析、配置无明文泄漏、目标端尚未接受业务写入。

### M4：执行源端最终停写冷备

输入：源端任务清空状态、T9-4.7 冷备工具。

执行：

1. 停止 Web 和 Worker 接受新请求，确认 Celery 队列为空。
2. 使用 `backup_cold.sh --apply` 生成新的数据归档、同期 `.env`、Manifest 和双方 SHA-256。
3. 对归档执行 `sha256sum -c`，记录源端备份点业务指纹。
4. 冷备后源端保持维护/只读状态，不能与香港目标同时产生新写入。

输出：本次迁移专用冷备，不使用 2026-08-23 的旧归档替代。

验收：冷备成功、校验和通过、源端数据服务可恢复但不继续写入。

### M5：加密传输与目标独立恢复

输入：迁移专用冷备和目标运行时。

执行：

1. 通过 SSH/SCP 传输归档、同期环境副本和校验文件，禁止通过公共对象链接传递 `.env`。
2. 在目标端再次执行 SHA-256 校验。
3. 先恢复到独立数据根和独立 Compose Project，不直接覆盖目标生产数据根。
4. 只启动 API 和存储依赖，不发布 Web 端口。
5. 使用 T9-4.7 验证器比较 MongoDB BSON 内容 Hash、Milvus Strong 行数/元数据、MinIO 全对象
   Hash、Redis 状态和当前检索烟雾。

输出：通过对账的目标独立恢复副本。

验收：所有跨存储内容级指纹与源端备份点一致，差异集合为空。

### M6：提升恢复副本并启动生产 Compose

输入：已通过对账的独立恢复副本。

执行：

1. 停止独立恢复 Project，将已验证数据根提升为目标生产数据根。
2. 使用生产 Project `semikb` 和同期环境启动完整 Compose。
3. 等待所有 Healthcheck，使用 Celery ping 验证 Worker。
4. 通过目标主机 `localhost` 和强制 Host Header 验证页面、API、SSE 和资产代理。

输出：仅在目标主机内部可验收的完整 SemiAtlas。

验收：所有容器健康、Worker 返回 `pong`、无 OOM/重启循环，源端指纹仍匹配。

### M7：配置域名和 HTTPS

输入：已健康的目标生产 Compose、两个已解析域名。

执行：

1. 复用现有 Nginx，增加 `semiatlas.cn` 与 `www.semiatlas.cn` 的 `server_name`。
2. 使用 Docker 化 Certbot 的 HTTP-01 流程申请双域名 SAN 证书，不引入新的常驻反向代理。
3. 发布 443，HTTP 统一 301/308 跳转到 `https://semiatlas.cn`，`www` 统一跳转到主域名。
4. 将证书以只读方式挂载给 Web，配置可审计的自动续期和续期后 Nginx reload。
5. 检查 CSP、短时图片、SSE、API 和前端资源不存在 HTTP Mixed Content。

输出：有效 HTTPS 入口。

验收：双域名证书有效、证书链完整、HTTP 跳转正确、SSE 不被代理缓冲。

### M8：公网验收和正式启用

输入：HTTPS 入口和本计划第 5 节验收项。

执行：

1. 从公网 DoH 验证两条 A 记录都指向香港 EIP。
2. 分别在关闭和开启 TUN 的浏览器环境验收，区分真实 DNS 与代理 Fake-IP。
3. 执行 T9-4.9 九场景最终演示、容量烟雾、安全黑盒和真实浏览器点击。
4. 验收全部通过后解除维护状态，记录启用时间和目标指纹。

输出：公开可访问的 `https://semiatlas.cn`。

验收：第 5 节所有 Go-Live 门禁通过。

### M9：观察期与源端退役

输入：目标正式启用时间。

执行：

1. 至少观察 24 小时；记录健康、错误、容器重启、磁盘增长、证书和 Provider 失败。
2. 观察期内保留源服务器、实例外冷备和离线包，不在两端同时写入。
3. 本项目不释放深圳 ECS；香港环境稳定后由用户自行决定和操作释放。
4. 香港抢占式实例若被回收，创建替代实例、重新绑定原 EIP，并使用实例外离线包与冷备重建全栈。

输出：稳定运行记录和源端退役建议。

验收：观察期无不可接受错误，实例外恢复材料完整；本项目未执行旧服务器释放操作。

## 5. 验收计划

### A1：基础设施与公网面

- 目标为 4 vCPU/8 GiB，磁盘空间满足当前 Demo；验收报告明确云盘会随抢占回收丢失数据。
- EIP 为 `47.76.218.205`，`@` 与 `www` 的权威 DNS 解析一致。
- 公网只开放 22、80、443；MongoDB、Milvus、双 MinIO、etcd、Redis 均不可从公网连接。
- `.env` 权限为 `0600`；迁移期使用用户已授权的测试密码，秘密值不得进入命令输出或验收证据。

### A2：制品一致性

- 迁移 Commit、源码归档 Commit、离线 Manifest Commit 完全一致。
- `source.tar.gz`、`images.tar`、冷备归档和同期环境副本 SHA-256 全部通过。
- 10 个运行镜像 ID 与离线 Manifest 一致，不发生隐式 `latest` 升级。

### A3：跨存储数据一致性

- MongoDB 所有受控业务集合执行内容级聚合 Hash 对账。
- Milvus Active Alias、物理 Collection、Strong `count(*)` 和元数据 Hash 一致。
- `semikb-raw`、`semikb-derived` 的对象路径、字节数和内容 Hash 一致。
- Redis 队列和任务状态一致，不把运行中任务迁移为成功。
- Thread、Checkpoint、消息请求、Trace、入库、语料标准化、文档治理和评估记录可读取。

验收值从本次最终备份点动态冻结，不把旧的 149 行或历史对象数硬编码为本次期望值。

### A4：服务健康与资源

- API、Web、MongoDB、Milvus、双 MinIO、etcd、Redis 全部 healthy。
- Worker Celery ping 返回 `pong`，并保持 `concurrency=1`。
- 无容器重启循环、`OOMKilled=false`，宿主机可用内存不少于 2 GiB。
- 日志轮转仍为 `20m x 3`，根盘和数据盘增长可解释。

### A5：核心业务闭环

复跑 T9-4.9 的九类场景：

1. 普通交流不触发 RAG。
2. SOP 问答返回结构化调查卡和受控证据。
3. 证据追问复用证据账本。
4. 同线程历史回顾准确。
5. 两轮澄清后恢复原任务。
6. 文本召回真实图片并自动预览首图。
7. 查询、危险写入拒绝和报告任务具有独立终态。
8. Trace 显示 Dense/Sparse、RRF、Reranker、截断和 Provider 审计。
9. 入库任务中心、知识文档管理和离线评估可以读取真实数据。

所有场景要求 HTTP 5xx、业务错误和权限泄露均为 0。

### A6：域名、TLS 与浏览器

- `https://semiatlas.cn` 返回 200，证书 SAN 同时包含 apex 和 `www`。
- `http://semiatlas.cn`、`http://www.semiatlas.cn`、`https://www.semiatlas.cn` 正确跳转主域名。
- 页面、API、SSE 和图片全部使用 HTTPS，无 Mixed Content、证书告警或重复重定向。
- 桌面 `1440 x 900` 和移动 `390 x 844` 完成真实点击与截图。
- 输入器收起/展开按钮不重叠，澄清时输入区保持完整可见。
- 浏览器 Console 为 0 error/warning，刷新后线程和最后回复保持一致。

### A7：性能与容量非回归

- 健康接口 P95 小于 1 秒。
- SSE accepted P95 小于 100 ms。
- 首 Delta P95 不高于 25 秒，端到端 P95 不高于 30 秒。
- 执行既有 `1 -> 2 -> 3` 有界并发、1 个入库和 1 个 Full 评估，不执行无界压力测试。
- 无 OOM、无意外重启；若远程 Provider 抖动，必须通过 Trace 与主机资源采样区分网络/Provider 和 ECS 瓶颈。

### A8：安全与权限

- 访问码缺失/错误返回 401，连续错误可触发 429。
- 无效 JWT、越权访问、跨用户线程分别满足 401/403/404 契约。
- 图片未授权和短时链接过期返回 403。
- Git、镜像配置、静态资源和应用日志中真实密钥扫描为 0 命中。
- Nginx 日志不记录对象签名 Query 和 Referer。
- `22/tcp` 在迁移期只作为受控例外，密钥登录完成后关闭密码登录。

### A9：抢占恢复与回滚准备

- EIP 独立保留，目标云盘随实例释放且没有自动快照；该风险在验收报告中保持显式可见。
- 至少一份冷备、同期环境副本和离线应用包复制到香港实例之外，并通过 SHA-256 校验。
- 不主动触发真实抢占回收；恢复 Runbook 明确新建实例、绑定原 EIP、加载离线包、恢复冷备、启动
  Compose 和业务验收顺序。

## 6. Go/No-Go 与回滚

### Go 条件

- A1 至 A9 全部通过。
- 跨存储差异为空，HTTPS 和核心演示闭环通过。
- 验收报告不包含凭据，旧服务器和本次冷备仍可用。

### No-Go 条件

- 任一内容 Hash、Active Alias、对象清单或权限结果不一致。
- HTTPS 无效、页面存在 Mixed Content、SSE 被缓冲或核心演示场景失败。
- 容器 OOM/循环重启、存储端口暴露或凭据泄漏。
- 迁移后产生了无法解释的新写入分支。

### 回滚策略

1. 公网启用前失败：停止目标生产 Project，保留目标数据和证据；源端解除维护并恢复直接 IP 服务。
2. 公网启用后且目标尚无新写入：停止目标，源端解除维护；域名不能直接回指未备案的深圳 ECS，
   因此域名显示维护页，面试紧急入口使用旧公网 IP。
3. 目标已经产生新写入：先对目标执行新的停写冷备，禁止直接用旧源快照覆盖；经数据分支审计后再决定恢复方向。
4. 香港抢占实例被回收：保留原 EIP，创建替代实例，加载实例外离线包和最新冷备后重新绑定 EIP。

## 7. 预计维护时间

基于 T9-4.7 已测结果，源端冷备停写约 67 秒，独立恢复准备与启动约 39 秒。考虑跨地域传输、镜像加载、
TLS 和完整验收，本次首次迁移建议预留 60 至 90 分钟操作窗口；真正不可写窗口预计 5 至 15 分钟。
实际时间必须以当次归档大小、深圳到香港链路和镜像加载速度记录，不把历史耗时作为保证值。
