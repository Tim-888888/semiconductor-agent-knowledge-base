# T8 浏览器验收

## 验收范围

- 工程师工作台接入 T6 连续线程、结构化追问、证据账本、模型警告和受控图片。
- 可解释检索面板接入 T5 Trace，展示 Dense/Sparse/HyDE/RRF/Rerank、动态截断、排除原因和组件耗时。
- 入库任务中心通过 multipart API 创建 T4 Job，展示阶段、进度、产物、事件历史和安全重试入口。
- 离线评估页接入 T7 不可变数据集、四档 Profile、异步运行、Baseline 差异、失败 Case 和专用 Trace 下钻。
- 使用真实 API、Celery Worker、Redis、MongoDB、Milvus、MinIO、BGE-M3、qwen3-rerank 和条件 Luna HyDE，不以接口响应替代浏览器验收。

## 浏览器点击验收

1. 在工程师工作台输入“最近蚀刻良率下降，可能是什么原因？”，系统暂停线程并要求补充 Product、时间范围和 Tool/Chamber。
2. 补充 `P-ALPHA / ETCH-03 / Chamber B / 最近24小时 / LOT-A100` 后恢复同一线程，页面展示已知事实、未知项、下一步和证据账本。
3. 点击 Trace 入口后选择完整多路召回样例；确认 5 个候选、4 个入选、1 个因 `below_rerank_threshold` 排除，并实际点击筛选按钮。
4. 点击 `T4-IMG-ETCH-03-EDGE-RING`，通过资产 API 重鉴权后成功显示 MinIO 中的真实晶圆 PNG。
5. 通过页面文件选择器上传 `t8-browser-ingestion-sample.md`。任务 `ing_6c49f3cd027f4a8096c51116b5329f5d` 从排队依次经过校验、解析、质量检查、向量化、暂存并发布，生成 3 个 Chunk。
6. 从离线评估页创建 Full 运行 `eval_d679b0f4c9ae42fab3e8319f8cd5db2f`，以 reranked 运行作为 Baseline；Worker 完成 7 个 Case，页面展示指标差异、唯一失败 Case 和 `trace_534bafc055cd4611ae8829f01f365b8b` 下钻。
7. 切换 390 x 844 移动视口，点击工作台、Trace 和评估导航；确认导航、表格、消息、输入区和详情区域无重叠。页面切换后 `scrollY=0`。
8. 浏览器控制台最终为 0 条 warning/error，恢复默认视口后关闭验收页。

## 评估发现

新发布的浏览器验收文档使 Full 运行的无证据负例误召回了
`UI-DEMO-69957302-R1-002`，导致 MRR、nDCG、无证据准确率和通过率相对 reranked
Baseline 回退。该结果不覆盖 T7 的冻结基线；它证明知识库新增内容后，评估页能够发现检索回归。
后续应在 T9 演示脚本中把“入库后自动触发黄金集回归”作为发布门禁示例。
