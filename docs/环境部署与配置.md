# 环境部署与配置

## `.env` 位置

本地和服务器均将真实 `.env` 放在项目根目录。阿里云建议固定部署路径：
`/opt/semiconductor-agent-knowledge-base/.env`，权限设置为 `600`，由部署用户持有。

根目录 Docker Compose 使用同目录 `.env`。T9-2 后不再直接执行裸 `docker compose up`，首次部署
必须经过配置生成、主机预检和受控初始化：

```bash
cd /opt/semiconductor-agent-knowledge-base
./scripts/deployment/host_preflight.sh .env
./scripts/deployment/deploy.sh --seed-demo
```

`.env` 永不提交；只提交 `.env.example`。

本地验证 Docker 前需先启动 Docker Desktop 的 Linux containers engine。若 `docker compose build`
提示 `dockerDesktopLinuxEngine` 不存在，先在 Docker Desktop 中等待 Engine 状态变为 Running，再重试；
这不会影响 Python/Vite 直接运行的 Demo。

## T9-2 全栈部署制品

服务器 `.env` 不应手工复制旧存储地址。先在本地运行：

```powershell

  --source .env `
  --output data/runtime/deployment/.env.server
```

## T9-1 阿里云资源基线

当前 CentOS 虚拟机的只读审计已经完成，但其约 4 GiB 内存低于 Milvus Standalone 的 8 GiB

- 公网只开放 80/443，22 仅授权固定 IP；所有数据库、对象存储和缓存端口只走内部网络。

资源估算见 `docs/T9-1部署环境审计与ECS资源估算.md`；T9-2 制品证据见
`docs/T9-2生产部署产物加固验收.md`。当前仍不把 T9 标记为完成。

## 存储初始化顺序

全新空环境填写 `.env` 后执行：

```powershell
conda run -n dl python -m semikb.storage.preflight
conda run -n dl python -m semikb.storage.provisioning
conda run -n dl python -m semikb.storage.verifier
```

已有 T9-4.4.3 环境升级到 T9-4.4.4 时，先执行窄范围迁移，再做完整核验：

```powershell
conda run -n dl python -m semikb.storage.preflight
conda run -n dl python -m semikb.storage.t9444_table_assets_migration
# 审批 dry-run 动作和快照后：
conda run -n dl python -m semikb.storage.t9444_table_assets_migration --apply
conda run -n dl python -m semikb.storage.verifier
```

`preflight` 只检查连接，`verifier` 只读核验 Collection、索引、Bucket 隐私、Milvus Schema/Alias 及
Redis 安全与持久化设置。若 verifier 返回非零退出码，必须先审查差异。

`provisioning` 只用于初始化新资源。若既有 MongoDB 索引与目标契约不一致，它会停止并要求审批迁移，
不会自动修改索引；初始化仅涉及 `semikb` 所属的 Mongo Collection 索引、私有
`semikb-raw`/`semikb-derived` Bucket 和新的 Milvus 物理 Collection，**不会**自动切换
`semikb_chunks_active` Alias，也不会删除任何现有数据。只有在暂存数据完成质量验收后，才允许
通过发布流程切换 Alias。

历史环境若仍未完成 T2/T6 迁移，可分别使用 `python -m semikb.storage.mongo_index_migration` 和
`python -m semikb.storage.t6_mongo_migration`。两者默认只保存快照并输出动作清单。只有经过审批后才可增加
`--apply`；命令强制限定 `semikb` 数据库、空 Collection 和已批准旧索引，发现非空数据或未知索引
会在任何写操作前停止。

T9-4.4.4 命令是新增 `table_assets` Collection 的窄范围 dry-run。确认计划与快照后才可增加
`--apply`；回滚使用 `--rollback <snapshot-path>`。迁移和回滚都要求该 Collection 为空，避免删除已经
入库的表格资产。新建空环境仍可由 provisioning 直接创建目标索引。

T9-4.4.5 在只读 API 镜像上的实际迁移命令需要把快照目录挂载到容器，并只让一次性迁移进程以 root
写入该宿主机备份目录；API/Worker 常驻容器仍保持 `10001:10001` 和只读文件系统：

```bash
cd /opt/semiconductor-agent-knowledge-base
mkdir -p /opt/semiconductor-agent-knowledge-base-backups
chmod 700 /opt/semiconductor-agent-knowledge-base-backups

# dry-run
docker compose --env-file .env -f docker-compose.prod.yml run --rm --no-deps \
  --user 0:0 \
  -v /opt/semiconductor-agent-knowledge-base-backups:/backups \
  api python -m semikb.storage.t9444_table_assets_migration \
  --snapshot-path /backups/t9445-table-assets-preflight.json

# 仅在 dry-run 只有批准的两个 create index 动作时执行
docker compose --env-file .env -f docker-compose.prod.yml run --rm --no-deps \
  --user 0:0 \
  -v /opt/semiconductor-agent-knowledge-base-backups:/backups \
  api python -m semikb.storage.t9444_table_assets_migration --apply \
  --snapshot-path /backups/t9445-table-assets-before-apply.json

chmod 600 /opt/semiconductor-agent-knowledge-base-backups/t9445-table-assets-*.json
```

应用后必须再次 dry-run 并得到 `actions: []`。随后只可使用 `--no-deps` 重建 API/Worker/Web；重建前后
逐一比对 MongoDB、Milvus、两个 MinIO、etcd 和 Redis 容器 ID，不一致时立即停止验收并调查。

## LLM 主备路由

一期配置 `closeai` 为主 Provider、`qwen` 为降级 Provider。主模型使用
`gpt-5.6-luna`，降级模型保留 `qwen-flash`。Provider 网关只暴露模型名、成功状态和用量，
异常信息不会包含 API Key 或 Endpoint。原有 `LLM_API_BASE_URL`、`LLM_API_KEY`、
`LLM_MODEL` 仅作为 Qwen 配置的兼容别名，新部署应填写明确的 `QWEN_*` 变量。

CloseAI 的 Chat Completions 兼容层使用 `max_completion_tokens`，支持
`reasoning_effort=none`、`verbosity=low` 和 JSON 结构化输出。调用中不发送
`temperature=0` 或旧的 `max_tokens` 参数。真实接口烟雾验证命令：

```powershell
conda run -n dl python scripts/verify_llm_gateway.py
```

默认只验证主 Provider，避免主服务配置错误被降级结果掩盖；需要验证运行时降级链路时显式增加
`--allow-fallback`。当前第三方代理只允许处理模拟数据与公开资料；接入真实工厂 SOP、Recipe、
YMS/DMS 数据前，必须完成数据留存、模型映射、日志、地域和 SLA 审查。

T9-4.1 流式能力探测使用脱敏命令：

```powershell
conda run -n dl python scripts/verify_llm_streaming.py --provider all
```

命令逐一调用主备 Provider，不做 fallback，因此不会把备用成功误记为主模型成功。输出只包含模型名、
事件/Delta 数量、时延、内容长度和 SHA-256，不输出 Endpoint、API Key、原始答案或推理内容。
CloseAI Luna 实测以 `finish_reason=stop` 后正常 EOF 结束，Qwen 以 `[DONE]` 结束；解析器只接受这两种
明确终止，缺少 `[DONE]` 且没有 `finish_reason` 的残缺流必须失败。

T9-4.2 已把流式能力接入公网工作台。Nginx 为
`/api/v1/threads/{thread_id}/messages/stream` 使用独立正则路由，关闭 `proxy_buffering`、
`proxy_cache` 和 `gzip`，并返回 `X-Accel-Buffering: no`。前端使用 POST `fetch + ReadableStream`，
不能改为不支持 JSON 请求体和 Bearer Token 的原生 `EventSource`。

部署 SSE 相关更新时，继续使用根目录生产 Compose，只重建应用容器：

```bash
cd /opt/semiconductor-agent-knowledge-base
docker compose --env-file .env -f docker-compose.prod.yml build api worker web
docker compose --env-file .env -f docker-compose.prod.yml up -d api worker
docker compose --env-file .env -f docker-compose.prod.yml up -d --force-recreate web
```

最后一步强制重建 Web，是为了让 Nginx 刷新 API 容器地址和最新前端静态资源。上述命令不得改写或
删除 MongoDB、Milvus、MinIO、etcd、Redis 的数据卷。真实 `.env` 固定保留在项目根目录且权限为
`600`，部署记录和 Git 不得包含访问码、密码或 API Key。

T5 真实检索基线使用在线 Qwen 原生 Dense/Sparse、Milvus 活动别名和 Qwen Reranker。
完整在线验收命令为：

```powershell
conda run -n dl python scripts/verify_t5_retrieval.py
```

`HYDE_ENABLED=true` 代表允许按问题路由条件启用，不代表每个问题都调用 HyDE。当前小型黄金集
强制 HyDE 没有提升 Recall/MRR 且增加明显延迟，因此不得改成无条件调用。

Embedding 空间变更必须创建新物理 Collection，不能覆盖当前活动索引。迁移命令默认 dry-run：

```powershell
conda run -n dl python scripts/migrate_embedding_index.py --target-index-version v4
conda run -n dl python scripts/migrate_embedding_index.py --target-index-version v4 --build
conda run -n dl python scripts/migrate_embedding_index.py --target-index-version v4 --publish
```

`--build` 只在线重编码、读回校验和自检索探测，不能切换 Alias；必须在目标物理 Collection 上
完成 T5/T7 影子评估。`--publish` 只发布已验证的候选，并在失败时恢复原 Alias。旧 Collection
保留到人工确认回滚窗口结束，不自动删除。当前 v4 已完成发布；命令中的目标版本应按下一次
Embedding 空间变更选择新值，不能覆盖活动版本。

T4 可重复验收命令为 `python scripts/verify_t4_ingestion.py`。脚本会写入两条带 `T4-` 前缀的
合成资料，不会修改 MongoDB、Milvus、MinIO、Attu 或 Redis 的容器、网络、端口和数据卷。
## T9-4.3.1 会话上下文升级

升级前先确认 API/Worker 无正在执行的会话，并在项目根目录运行：
