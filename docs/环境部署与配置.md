# 环境部署与配置

## `.env` 位置

本地和服务器均将真实 `.env` 放在项目根目录。阿里云建议固定部署路径：
`/opt/semiconductor-agent-knowledge-base/.env`，权限设置为 `600`，由部署用户持有。

根目录 Docker Compose 使用同目录 `.env`。启动命令固定为：

```bash
cd /opt/semiconductor-agent-knowledge-base
docker compose --env-file .env -f docker-compose.prod.yml up -d
```

`.env` 永不提交；只提交 `.env.example`。

本地验证 Docker 前需先启动 Docker Desktop 的 Linux containers engine。若 `docker compose build`
提示 `dockerDesktopLinuxEngine` 不存在，先在 Docker Desktop 中等待 Engine 状态变为 Running，再重试；
这不会影响 Python/Vite 直接运行的 Demo。

## 当前开发拓扑

Windows 本地运行 API、Celery Worker 与 React 开发服务器，按 `.env` 连接 CentOS
上的 MongoDB、Milvus 和 MinIO。Redis 是新增 Docker 服务；阿里云阶段将 API、Worker、
Web 和 Redis 容器化。现有存储镜像版本确认后再生成全栈部署 Compose。

## 必填配置

- `MONGODB_URI`、`MILVUS_URI`、`MINIO_ENDPOINT`、`REDIS_URL`
- `MINERU_API_BASE_URL`、`MINERU_API_KEY`
- `LLM_API_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`
- `ALIYUN_WEB_MCP_URL`、`ALIYUN_WEB_MCP_API_KEY`
- `BGE_M3_MODEL_PATH`、`BGE_RERANKER_MODEL_PATH`
- `MILVUS_INDEX_VERSION`、`MILVUS_REQUIRE_ACTIVE_ALIAS`
- `BGE_USE_FP16`、`EMBEDDING_BATCH_SIZE`

T4 验收基线使用 `MILVUS_INDEX_VERSION=v2`、`MILVUS_REQUIRE_ACTIVE_ALIAS=true` 和
`BGE_USE_FP16=false`。当前 Windows CPU 路径使用 FP32；编码器会拒绝 NaN/Inf 或维度不一致的
Dense 向量，避免坏向量进入 Milvus。

安装包含 BGE-M3 的开发依赖：

```powershell
conda activate dl
pip install -e ".[dev,rag]"
```

真实异步模式分别启动 API 和 Worker：

```powershell
uvicorn semikb.api.main:app --host 0.0.0.0 --port 8000
celery -A semikb.workers.celery_app:celery_app worker --loglevel=INFO
```

## 存储初始化顺序

填写 `.env` 后，先执行：

```powershell
conda run -n dl python -m semikb.storage.preflight
conda run -n dl python -m semikb.storage.verifier
conda run -n dl python -m semikb.storage.provisioning
conda run -n dl python -m semikb.storage.mongo_index_migration
```

第一个命令只检查连接，第二个命令只读核验 Collection、索引、Bucket 隐私、Milvus Schema/Alias
及 Redis 安全与持久化设置。若 verifier 返回非零退出码，必须先审查差异。

第三个命令只用于初始化新资源。若既有 MongoDB 索引与目标契约不一致，它会停止并要求审批迁移，
不会自动修改索引；初始化仅涉及 `semikb` 所属的 Mongo Collection 索引、私有
`semikb-raw`/`semikb-derived` Bucket 和新的 Milvus 物理 Collection，**不会**自动切换
`semikb_chunks_active` Alias，也不会删除任何现有数据。只有在暂存数据完成质量验收后，才允许
通过发布流程切换 Alias。

第四个命令是 MongoDB 索引迁移 dry-run，默认只保存快照并输出动作清单。只有经过审批后才可增加
`--apply`；命令强制限定 `semikb` 数据库、空 Collection 和已批准旧索引，发现非空数据或未知索引
会在任何写操作前停止。

MinerU 适配器采用当前 Precision Extract API：Worker 申请签名上传地址、上传原件、轮询批量
解析结果、从 ZIP 中提取 `full.md`。应将 `MINERU_API_BASE_URL` 设置为 `https://mineru.net`，
并配置 Token 型 `MINERU_API_KEY`。官方 API 说明见 [MinerU 文档](https://mineru.net/doc/docs/index_en/)。

T4 可重复验收命令为 `python scripts/verify_t4_ingestion.py`。脚本会写入两条带 `T4-` 前缀的
合成资料，不会修改 MongoDB、Milvus、MinIO、Attu 或 Redis 的容器、网络、端口和数据卷。
