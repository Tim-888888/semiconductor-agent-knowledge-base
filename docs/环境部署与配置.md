# 环境部署与配置

## `.env` 位置

本地和服务器均将真实 `.env` 放在项目根目录。阿里云建议固定部署路径：
`/opt/semiconductor-agent-knowledge-base/.env`，权限设置为 `600`，由部署用户持有。

根目录 Docker Compose 使用同目录 `.env`。启动命令固定为：

```bash
cd /opt/semiconductor-agent-knowledge-base
docker compose --env-file .env -f docker-compose.prod.yml up -d
```

`.env` 永不提交；只提交 `.env.example`。

本地验证 Docker 前需先启动 Docker Desktop 的 Linux containers engine。若 `docker compose build`
提示 `dockerDesktopLinuxEngine` 不存在，先在 Docker Desktop 中等待 Engine 状态变为 Running，再重试；
这不会影响 Python/Vite 直接运行的 Demo。

## 当前开发拓扑

Windows 本地运行 API、Celery Worker 与 React 开发服务器，按 `.env` 连接 CentOS
上的 MongoDB、Milvus 和 MinIO。Redis 是新增 Docker 服务；阿里云阶段将 API、Worker、
Web 和 Redis 容器化。现有存储镜像版本确认后再生成全栈部署 Compose。

## 必填配置

- `MONGODB_URI`、`MILVUS_URI`、`MINIO_ENDPOINT`、`REDIS_URL`
- `MINERU_API_BASE_URL`、`MINERU_API_KEY`
- `LLM_PRIMARY_PROVIDER`、`CLOSEAI_BASE_URL`、`CLOSEAI_API_KEY`、`CLOSEAI_MODEL`
- `LLM_FALLBACK_PROVIDER`、`QWEN_API_BASE_URL`、`QWEN_API_KEY`、`QWEN_MODEL`
- `RERANK_PROVIDER`、`RERANK_API_BASE_URL`、`RERANK_API_KEY`、`RERANK_MODEL`
- `EMBEDDING_PROVIDER`、`EMBEDDING_API_BASE_URL`、`EMBEDDING_MODEL`
- `EMBEDDING_API_KEY`；留空时显式复用 `RERANK_API_KEY`
- `SPARSE_ENCODER_VERSION`、`EMBEDDING_DIM`、`EMBEDDING_BATCH_SIZE`
- `RETRIEVAL_RECALL_K`、`RETRIEVAL_RRF_K`、`RETRIEVAL_RERANK_MIN_SCORE`
- `ALIYUN_WEB_MCP_URL`、`ALIYUN_WEB_MCP_API_KEY`
- `AGENT_MAX_CLARIFICATION_ROUNDS`、`AGENT_ANSWER_MAX_OUTPUT_TOKENS`
- `MILVUS_INDEX_VERSION`、`MILVUS_REQUIRE_ACTIVE_ALIAS`

当前部署基线使用 `MILVUS_INDEX_VERSION=v3`、`MILVUS_REQUIRE_ACTIVE_ALIAS=true`、
`EMBEDDING_PROVIDER=qianwen`、`EMBEDDING_MODEL=qwen3.7-text-embedding` 和 1024 维 Dense。
Dense 调用在线服务并执行数量、维度、有限值和 L2 归一化检查；Sparse 使用无模型、CPU 可运行的
`lexical-hash-v1`，保留 Dense + Sparse + RRF 混合召回。API/Worker 不加载 Torch 或本地权重。

安装开发依赖：

```powershell
conda activate dl
pip install -e ".[dev]"
```

真实异步模式分别启动 API 和 Worker：

```powershell
uvicorn semikb.api.main:app --host 0.0.0.0 --port 8000
celery -A semikb.workers.celery_app:celery_app worker --loglevel=INFO
```

## 存储初始化顺序

填写 `.env` 后，先执行：

```powershell
conda run -n dl python -m semikb.storage.preflight
conda run -n dl python -m semikb.storage.verifier
conda run -n dl python -m semikb.storage.provisioning
conda run -n dl python -m semikb.storage.mongo_index_migration
conda run -n dl python -m semikb.storage.t6_mongo_migration
```

第一个命令只检查连接，第二个命令只读核验 Collection、索引、Bucket 隐私、Milvus Schema/Alias
及 Redis 安全与持久化设置。若 verifier 返回非零退出码，必须先审查差异。

第三个命令只用于初始化新资源。若既有 MongoDB 索引与目标契约不一致，它会停止并要求审批迁移，
不会自动修改索引；初始化仅涉及 `semikb` 所属的 Mongo Collection 索引、私有
`semikb-raw`/`semikb-derived` Bucket 和新的 Milvus 物理 Collection，**不会**自动切换
`semikb_chunks_active` Alias，也不会删除任何现有数据。只有在暂存数据完成质量验收后，才允许
通过发布流程切换 Alias。

第四个命令是 T2 通用 MongoDB 索引迁移 dry-run；第五个命令只处理 T6 的 Checkpointer、Store
和审计索引。两者默认只保存快照并输出动作清单。只有经过审批后才可增加
`--apply`；命令强制限定 `semikb` 数据库、空 Collection 和已批准旧索引，发现非空数据或未知索引
会在任何写操作前停止。

MinerU 适配器采用当前 Precision Extract API：Worker 申请签名上传地址、上传原件、轮询批量
解析结果、从 ZIP 中提取 `full.md`。应将 `MINERU_API_BASE_URL` 设置为 `https://mineru.net`，
并配置 Token 型 `MINERU_API_KEY`。官方 API 说明见 [MinerU 文档](https://mineru.net/doc/docs/index_en/)。

## LLM 主备路由

一期配置 `closeai` 为主 Provider、`qwen` 为降级 Provider。主模型使用
`gpt-5.6-luna`，降级模型保留 `qwen-flash`。Provider 网关只暴露模型名、成功状态和用量，
异常信息不会包含 API Key 或 Endpoint。原有 `LLM_API_BASE_URL`、`LLM_API_KEY`、
`LLM_MODEL` 仅作为 Qwen 配置的兼容别名，新部署应填写明确的 `QWEN_*` 变量。

CloseAI 的 Chat Completions 兼容层使用 `max_completion_tokens`，支持
`reasoning_effort=none`、`verbosity=low` 和 JSON 结构化输出。调用中不发送
`temperature=0` 或旧的 `max_tokens` 参数。真实接口烟雾验证命令：

```powershell
conda run -n dl python scripts/verify_llm_gateway.py
```

默认只验证主 Provider，避免主服务配置错误被降级结果掩盖；需要验证运行时降级链路时显式增加
`--allow-fallback`。当前第三方代理只允许处理模拟数据与公开资料；接入真实工厂 SOP、Recipe、
YMS/DMS 数据前，必须完成数据留存、模型映射、日志、地域和 SLA 审查。

T5 真实检索基线使用在线 Qwen Dense、CPU 词法 Sparse、Milvus 活动别名和 Qwen Reranker。
完整在线验收命令为：

```powershell
conda run -n dl python scripts/verify_t5_retrieval.py
```

`HYDE_ENABLED=true` 代表允许按问题路由条件启用，不代表每个问题都调用 HyDE。当前小型黄金集
强制 HyDE 没有提升 Recall/MRR 且增加明显延迟，因此不得改成无条件调用。

Embedding 空间变更必须创建新物理 Collection，不能覆盖当前活动索引。迁移命令默认 dry-run：

```powershell
conda run -n dl python scripts/migrate_embedding_index.py --target-index-version v4
conda run -n dl python scripts/migrate_embedding_index.py --target-index-version v4 --apply
```

`--apply` 会在线重编码、读回校验、自检索探测、切换 Alias 并更新 MongoDB 发布记录；任一步异常
都会恢复原 Alias。旧 Collection 保留到人工确认回滚窗口结束，不自动删除。
目标版本必须显式提供且不同于当前 `MILVUS_INDEX_VERSION`；上例 v4 仅表示下一次迁移，不应在
模型、维度或 Sparse 版本未变化时执行。

T4 可重复验收命令为 `python scripts/verify_t4_ingestion.py`。脚本会写入两条带 `T4-` 前缀的
合成资料，不会修改 MongoDB、Milvus、MinIO、Attu 或 Redis 的容器、网络、端口和数据卷。
